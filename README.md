# 블로그 이전 통합 도구 — 네이버 / 티스토리 → 구글 블로거 (Netlify 웹 버전)

한 페이지에서 상단 탭으로 **네이버 → 블로거** 와 **티스토리 → 블로거** 를 전환합니다.
주소에 `?src=naver` / `?src=tistory` 를 붙이면 해당 탭으로 바로 열립니다.

## 구조
```
├─ netlify.toml                    # 빌드(난독화) + 배포 설정
├─ package.json · build.js         # public/ -> dist/ 난독화 빌드
├─ netlify/functions/
│   ├─ naver.js                    # 네이버 읽기 전용 프록시
│   └─ tistory.js                  # 티스토리 읽기 전용 프록시 (같은 출처 확인·호출 제한 추가)
└─ public/                         # 읽기 쉬운 원본 (dist/ 가 실제 배포물)
    ├─ index.html · app.js         # 화면 / 동작 (탭 전환, 소스별 설정·기록)
    ├─ worker.js                   # Pyodide 워커 (선택한 소스의 코어만 로드)
    ├─ core_naver.py               # 네이버 변환 코어
    ├─ core_tistory.py             # 티스토리 변환 코어
    └─ config.js · sw.js · privacy/terms.html · sitemap.xml · robots.txt · 이미지
```

## 동작 요약
- 소스별로 **설정·이전 기록을 따로** 저장합니다 (기존 `n2b_*`, `t2b_*` 저장값 그대로 사용 → 기존 기록 유지).
- **구글 로그인과 대상 블로거 선택은 공유**합니다. 한 번 로그인하면 탭을 바꿔도 이어서 씁니다.
- 이전 기록 내보내기/가져오기는 현재 탭 기준입니다 (`migrated.json` / `migrated_tistory.json`).
- 이전·목록 작업 중에는 탭 전환이 잠깁니다.

## 배포
```
npm i -g netlify-cli
cd blogmigrate
netlify login
netlify deploy --prod --build --create-site 내사이트이름
```
(GitHub 연동이면 push 만 하면 Netlify 가 `npm install && npm run build` 후 `dist/` 를 게시합니다.)

## 로컬 테스트
```
netlify dev --dir public     # http://localhost:8888  (난독화 없는 원본)
```
구글 콘솔의 **승인된 자바스크립트 원본**에 배포 주소와 `http://localhost:8888` 을 추가하세요.
`file://` 로 index.html 을 직접 열면 프록시와 구글 로그인이 동작하지 않습니다.

## 난독화 빌드
- `npm run build` 난독화 / `npm run build:debug` 난독화 없이 dist 생성
- `DOMAIN_LOCK=itnes.site,www.itnes.site npm run build` : 지정 도메인에서만 동작
- 브라우저 코드는 난독화해도 완전히 숨길 수 없습니다(읽기 어렵게 만드는 수준).

## 환경 변수 (Netlify)
- `ALLOWED_HOSTS` : 프록시 호출을 허용할 추가 도메인(쉼표 구분). 두 프록시에 공통 적용.

## 알아둘 점
- 두 프록시의 호출 제한은 IP 당 1분 (네이버 120회 / 티스토리 240회) 입니다.
- 티스토리는 공개 글만 가져오며, 이미지는 티스토리 서버 주소를 그대로 연결합니다.
- `privacy.html`, `terms.html` 은 기존 네이버 버전 문구 그대로입니다. 티스토리 지원 사실을 반영하려면 문구를 수정하세요.

## 이미지 누락(깨짐) 수정 내역 (티스토리)
- 원인: 폭 966px 초과 이미지를 `img1.daumcdn.net/thumb/...` 크기 변환 주소로 바꿀 때, 서명(`credential`·`signature`)이 붙은 티스토리 이미지 주소가 거부되어 큰 이미지만 깨졌습니다.
- `core_tistory.py`: 서명이 붙은 주소는 원본 주소를 그대로 사용하고, 서명 없는 주소만 크기 변환을 우선 시도합니다. `data-src`, `srcset`, 원본(`data-url`), 서명을 뗀 기본 주소를 대체 후보(`data-fb`)로 함께 기록합니다.
- `app.js`: 발행 직전에 브라우저에서 모든 이미지가 실제로 열리는지 점검하고, 안 열리면 대체 주소로 자동 교체합니다. 끝까지 안 열리는 이미지는 로그에 주소와 순번이 표시됩니다.
- 옵션 ③ 의 "이미지 주소 점검 · 자동 대체" 로 끌 수 있습니다 (기본 켜짐).
- 이미 이전된 글은 수정되지 않습니다. 블로거에서 해당 글을 삭제한 뒤, 이 앱에서 다시 이전해 주세요.

## 화면 순서 / 옵션 (v3)
- 순서: ① 소스 블로그 → ② 구글 블로거 → ③ 글 선택·이전 → ④ 옵션
- 옵션은 기본으로 펼쳐져 있고, 오른쪽의 "옵션 숨기기 / 옵션 보이기" 버튼으로 접고 펼 수 있습니다 (선택은 브라우저에 기억).

## 본문 일부 누락(첫 문단만 이전됨) 수정 내역 (티스토리)
- 증상: 첫 문단 뒤의 소제목·본문·이미지가 통째로 빠지고 첫 문단과 원문 출처만 블로거로 이전됨.
- 원인 ① 티스토리가 본문 중간에 넣는 광고 래퍼(`revenue_unit_wrap`, `ins`) 안으로 뒤쪽 본문이 함께 파싱되면, 광고를 `decompose()` 할 때 뒤쪽 본문까지 같이 삭제됨.
- 원인 ② 클래스명에 `banner`/`ad` 등이 들어간 래퍼를 광고로 오인해 안쪽 본문 전체를 건너뜀.
- 원인 ③ 본문 HTML 에 짝 없는 `</div>` 가 있으면 본문 컨테이너가 중간에서 닫혀 나머지가 컨테이너 밖으로 밀려남.
- `core_tistory.py`: 광고 래퍼 안에 글자(30자↑)나 이미지가 있으면 광고 부분만 지우고 본문은 살림(`_ad_has_real_content`, `_remove_noise`). 컨테이너 바로 뒤 형제 요소 중 본문 조각을 이어 붙임(`_collect_cut_siblings`, 댓글·태그·공유·관련글 등을 만나면 중단). 복구가 일어나면 로그에 안내가 표시됨.
- `worker.js`/`build.js`: 캐시 버전을 `v=2` 로 올려 브라우저가 새 코어를 받도록 함.

### 2차 보강: 누락 자동 감지 · 재시도 (티스토리)
- 티스토리가 `og:description` 에 넣어 둔 본문 앞부분의 끝 16자가 변환 결과에 있는지 확인해 본문이 끊겼는지 판단합니다.
- 끊긴 것으로 보이면 ① 컨테이너 밖으로 밀려난 본문을 위쪽 4단계까지 이어 붙이기 ② 클래스·아이디 이름만으로 광고 판단하지 않기(안 닫힌 `form`/`video`/`ins` 가 본문을 감싼 경우 포함) ③ ①+② 순으로 자동 재시도합니다.
- 그래도 안 되면 로그에 `⚠ 본문이 일부만 추출됐을 수 있습니다` 경고를 남깁니다.

### 변경: 하단 "최초 게시일 · 원문" 줄 제거
- 블로거 글 맨 아래의 구분선과 `최초 게시일 YYYY-MM-DD · 원문: URL` 줄을 더 이상 만들지 않습니다.
- `add_source_link` 옵션과 설정 화면의 체크박스("하단에 원문 링크 추가")도 함께 삭제했습니다. (네이버·티스토리 공통)

### 추가: 로컬 실행 지원
- `server.js`, `start-local.bat`, `start-local.sh`, `README_LOCAL.md` 추가. Netlify 없이 `npm start` 로 실행할 수 있습니다. 자세한 내용은 `README_LOCAL.md`.
- `public/local.html` 추가: 로컬 사용 안내 + 실시간 상태 점검 페이지 (`/local.html` 또는 `/local`). 배포용 빌드(`dist/`)에는 포함되지 않습니다.
